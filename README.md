# Growtask Marketplace

Тестовое задание: маркетплейс на Vue 3 — корзина, оформление заказа и статус заказа.

## Что сделано

- **Корзина** (`/cart`) — список товаров из API с чекбоксами, степперами количества и удалением; тулбар «выбрать всё / очистить»; итоги с учётом скидок и промокода
- **Оформление заказа** (`/checkout`) — сводка заказа, форма покупателя с валидацией (имя и фамилия обязательны, телефон и почта — с проверкой формата), выбор способа оплаты, подсказки и блокировка сабмита при ошибках
- **Статус заказа** (`/checkout/success`) — экран успешного оформления с возвратом в корзину
- **Состояние** — корзина и промокод сохраняются в sessionStorage и восстанавливаются между страницами
- **Адаптив** — 4 брейкпоинта по макету: 414 / 768 / 1366 / 1920
- **Архитектура** — FSD-подобное разделение: `app` / `pages` / `widgets` / `features` / `entities` / `shared`
- **Качество** — ESLint + Prettier + husky pre-commit, unit и скриншот-тесты, CI-пайплайн
- **Деплой** — конфигурация Vercel (`vercel.json`) со SPA-rewrite и проксированием API

## Стек

- **Vue 3** (Composition API) + **TypeScript**
- **Vite**
- **Pinia** — состояние корзины и оформления заказа
- **Vue Router** — маршруты `/cart`, `/checkout`, `/checkout/success`
- **vee-validate + zod** — валидация формы заказа
- **SCSS** (модули, токены, брейкпоинты 414 / 768 / 1366 / 1920)
- pnpm

## Запуск

```bash
pnpm install
pnpm dev        # dev-сервер на http://localhost:5173
```

Продакшен-сборка:

```bash
pnpm build      # проверка типов + сборка в dist/
pnpm preview    # локальный просмотр собранной версии
```

## Тесты

### Unit и интеграционные (Vitest)

Тестируют форму оформления заказа: zod-схему валидации, компоненты формы и полный флоу сабмита (ошибки, payload заказа, редирект).

```bash
pnpm test          # разовый прогон
pnpm test:watch    # watch-режим
```

### Скриншот-тесты (Playwright)

3 страницы (корзина, оформление заказа, заказ оформлен) на 4 вьюпортах — desktop 1920, laptop 1366, tablet 768, mobile 414. API замокан, корзина сеется через sessionStorage, поэтому скриншоты детерминированы. Базлайны лежат в `e2e/*.spec.ts-snapshots/`.

```bash
pnpm test:screenshots          # сравнение с базлайнами
pnpm test:screenshots:update   # перегенерация базлайнов
```

При первом запуске нужен установленный браузер:

```bash
pnpm exec playwright install chromium
```

Diff упавших тестов открывается через `pnpm exec playwright show-trace test-results/<папка>/trace.zip` или в HTML-отчёте.

> Скриншот-тесты не входят в CI: базлайны сгенерированы на macOS, а рендеринг шрифтов на Linux отличается — сравнение запускается локально перед пушем.

## CI/CD (GitHub Actions)

Пайплайн описан в `.github/workflows/` и запускается на push в `main`/`dev` и на все PR:

| Workflow            | Что делает                                                    |
| ------------------- | ------------------------------------------------------------- |
| `init-pipeline.yml` | Оркестратор: последовательно запускает stage-воркфлоу         |
| `test.yml`          | **lint** (ESLint) и **unit** (vitest) параллельными job'ами   |
| `build.yml`         | Сборка (`vue-tsc` + `vite build`) и выгрузка артефакта `dist` |

Слить PR со сломанными тестами или сборкой нельзя — pipeline упадёт на соответствующем этапе.

Деплой — Vercel подключается к репозиторию и деплоит `main` автоматически; настройки читаются из `vercel.json`.
